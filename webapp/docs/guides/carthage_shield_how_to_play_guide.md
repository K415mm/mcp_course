# Carthage Shield How To Play Guide

## 1) Goal Of The Game

Carthage Shield is a multi-team cyber-crisis tabletop simulation.  
Your objective is to make better national-level decisions than the adversary pressure and time constraints.

Success is measured by:

- Score gained from high-quality decisions and collective votes
- Quality of coordination between institutions
- Ability to communicate clearly under crisis pressure

## 2) Roles

### 2.1 Moderator (Game Master)

- Creates and controls the session
- Starts/pauses timer and advances phases
- Sends broadcasts, triggers injects and phantom pressure messages
- Opens/closes votes and awards points
- Assigns badges for exceptional performance

### 2.2 Teams

Typical teams:

- ANCS: national command and strategic coordination
- CERT: technical detection, analysis, and incident handling
- Finance: banking and payment sector continuity
- Transport: mobility and critical transport continuity
- E-Gov: citizen-facing digital public services
- Communication: media/public messaging and rumor management

### 2.3 Players And Captain

- Players join one team using display name
- First player in a team becomes captain automatically
- Team should designate who submits final decisions each phase

## 3) Session Lifecycle

1. Moderator creates session and shares session code.
2. Players join a team.
3. Moderator confirms readiness and starts Phase 0.
4. Teams process injects, discuss options, and submit decisions.
5. Moderator scores decisions, may run vote, and moves to next phase.
6. Final phase includes closure, badges, and debrief.

## 4) In-Game Actions

## 4.1 Submit Decision

Teams submit one or more structured entries:

- `decision`: concrete response action
- `escalade`: escalation/governance action
- `communication`: public or stakeholder message
- `question`: request for clarification to moderator

Good submissions are short, actionable, and justified.

## 4.2 Vote On Strategic Choices

- Moderator opens a vote question with options (A/B/C...)
- Each team votes once
- Closing vote computes tally
- If there is one winner and points are configured, all teams receive those points (collective strategy reward)
- Tie means no vote points

## 4.3 Receive Injects And Broadcasts

- Injects simulate new facts, uncertainty, and escalation
- Surprise injects can appear at any time
- Team-targeted injects are only visible to matching team
- Broadcasts are official moderator messages for all participants

## 5) Timer And Phase Discipline

- Timer is controlled by moderator and is server-authoritative
- When paused, remaining seconds are preserved
- Advancing phase resets context to next phase duration
- Final phase marks session as finished

Operational rule:

- Do not wait for perfect information
- Produce a justified decision before timer expires

## 6) Scoring Model (What Gives Points)

- Moderator-awarded decision quality points
- Strategic vote winner points (collective)
- Badge bonus points (+5 each currently)
- Manual score adjustment if facilitator needs correction

Avoid score loss by:

- Unstructured or contradictory decisions
- Missing escalation path
- Weak communication under public pressure
- Ignoring cross-sector dependencies

## 7) Playbook Per Phase (Recommended)

### Phase 0 - Opening

- Confirm command chain and team responsibilities
- Set communication protocol and reporting format

### Phase 1 - Detection

- Build initial incident picture (what, where, impact)
- Decide containment posture and escalation threshold

### Phase 2 - Amplification

- Prioritize essential services and business continuity
- Synchronize technical and policy decisions across teams

### Phase 3 - Media Crisis

- Publish one consistent official narrative
- Appoint spokesperson and define approved statements

### Phase 4 - Arbitration / National Choice

- Vote strategic posture with clear rationale
- Document trade-offs (security, continuity, diplomacy, public trust)

### Phase 5 - Closure

- Capture lessons learned and unresolved risks
- Convert lessons into concrete action items

## 8) Alignment Procedure For Tabletop And Standards

Use this checklist during each session.

- Pre-brief objective: map each phase to one capability objective (detect, contain, coordinate, communicate, recover)
- Evidence capture: require every team decision to include owner, action, deadline
- Escalation discipline: verify trigger conditions for national coordination
- Communication quality: check message accuracy, timing, and consistency
- Debrief quality: produce after-action list with corrective actions

Reference frameworks to align facilitation:

- ISO/IEC 27035 for incident lifecycle
- NIST SP 800-61 for containment and response logic
- ISO 22320 for command and coordination structure
- National cyber incident governance procedures in Tunisia (ANCS/CERT operating model)

## 9) Facilitator Tips For Better Outcomes

- Keep pressure realistic, not chaotic
- Score behavior quality, not speaking volume
- Reward cross-team collaboration explicitly
- Challenge assumptions with targeted injects
- End with measurable improvement actions

## 10) Quick Start (10 Minutes)

1. Create session and choose scenario.
2. Ensure all six teams are staffed.
3. Explain decision types and scoring.
4. Start timer for Phase 0.
5. Trigger first inject and ask for first structured decision.
6. Repeat cycle: inject -> discuss -> decide -> score -> advance.
7. Run final vote and debrief.

This sequence is enough to run a complete, standards-aligned tabletop session in Carthage Shield.
